# Unit tests

The unit tests use the SDK unit-test framework (`LedgerUT`), based on
[Unity](https://github.com/ThrowTheSwitch/Unity) and [CMock](https://github.com/ThrowTheSwitch/CMock).
It is documented in the SDK, in `cmake/USAGE.md`.

## Prerequisites

- CMake >= 3.10
- Ruby, used by CMock to generate the mocks
- libsodium (`libsodium-dev`), which computes the real hashes behind the crypto mocks
- Network access on the first configuration, to fetch Unity and CMock
- lcov >= 1.14, for the code coverage

`BOLOS_SDK` must point to the SDK, as it does in the `ledger-app-builder` Docker images.

## Layout

| Path | Content |
| --- | --- |
| `CMakeLists.txt` | Test declarations, one `ledger_unit_tests_add_test()` per test executable |
| `test_<name>.c` | Test executable `test_<name>` |
| `fakes/fake_crypto.c` | libsodium SHA-256, SHA-512, HMAC-SHA512 and PBKDF2 plugged into the SDK crypto mocks, and the device seed |
| `fakes/fake_sdk.c` | `TRY`/`THROW` context of the SDK |
| `fakes/glyphs.h`, `fakes/fake_glyphs.c` | Replacement of the glyphs generated by the app build |
| `cmake/FindSodium.cmake` | libsodium lookup |

The crypto mocks compute the real values: a test checks the recovery phrase against the BIP32
master key of the device, `REFERENCE_ROOT_KEY` or `REFERENCE_PASSPHRASE_ROOT_KEY`, computed
independently of the app code.

`test_ui` runs the UI on top of the real mnemonic code, with NBGL mocked: the callbacks record
the last use case started by the app in `screen`, and a test calls the callbacks it holds, as a
user action would. It is built with the SDK default target, Flex: the Nano code paths are not
covered.

## Build and run

In `tests/unit` folder:

```shell
cmake -B build -S .
cmake --build build
ctest --test-dir build --output-on-failure
```

A single test executable can also be run directly, for example `build/test_nbgl_mnemonic`.

## Code coverage

After running the tests:

```shell
cmake --build build --target generate_coverage
```

It outputs `build/coverage.info`, `build/coverage.xml`, and an HTML report in `build/coverage/index.html`.
